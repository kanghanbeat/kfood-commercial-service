### 지도 색 단순화 + 수도권 멤버 탭 (2026-07-11, 세션8 추가)

1. **색상 단순화(솔 요청)** — 시·도 채움색을 아주 연한 라벤더(#EFE7FB) 한 가지로 통일, **마우스를 올린 권역만 브랜드 진보라(#8500FF)**로 전환(콘텐츠 없는 권역은 연보라 #D9BFFF까지만 + 기본 커서 = 클릭 불가 힌트). 밀도별 색칠 제거. 서울·인천 소라벨은 밝은 배경에선 진보라, 호버(진보라 배경) 시 흰색으로 자동 전환.
2. **수도권 멤버 탭(솔 요청)** — `/regions?province=…` 페이지 제목 아래 탭 줄 추가: [수도권] [Seoul] [Incheon] [Gyeonggi] [전체 지역]. 서울처럼 콘텐츠가 많아질 지역을 시·도 단위로 나눠 본다. 탭 선택 시 지역 카드와 확대 지도 마커가 해당 시·도로 좁혀짐(예: Seoul 탭 → 카드 10개, 지도 마커 서울 1개). 멤버가 2개 이상인 권역(현재 수도권)에만 멤버 탭 표시.
3. 검증: 탭 5개 렌더·active 표시·클릭 필터 동작, 지도 기본색 #EFE7FB·호버 #8500FF 실측, 스크린샷 확인, tsc·eslint·build 통과. push 시 원격에 한빛 문서 커밋 2건 있어 merge 후 재검증하고 push(f5ec0bf).

### 울릉도·독도 상시 표시 + 지역 목록 확대 지도 (2026-07-11, 세션8 마감)

1. **울릉도·독도 항상 표시** — 울릉도는 원본 SVG(경북 path)에 지형이 있어 라벨만 추가, **독도는 통계청 경계 데이터에 지형이 없어 점으로 직접 그림**. 실비율 위치(x≈789)는 viewBox 우측에 잘려 라벨이 보이도록 살짝 안쪽(762) 배치 — 코드 주석에 명시.
2. **지역 목록 확대 지도** — `/regions?province=…`로 들어가면 상단에 해당 권역만 크게 보여주는 지도(`web/components/province-map.tsx`) 표시. 마커·이름 상시 노출, 마커 클릭 → 지역 상세. 권역별 viewBox는 `GROUP_VIEWBOXES`(수도권은 서해 도서 때문에 본토 중심으로 수동 조정).
3. 검증: /regions?province=gyeonggi에서 수도권 확대 지도 + 마커 8곳·이름 6개 렌더, 홈 지도에 Ulleungdo·Dokdo 라벨 표시 — 스크린샷 확인, tsc·eslint·build 통과.

### 지도 가시성 재설계: 라벨 상시 + 마커는 호버 시만 (2026-07-11, 세션8 후반)

솔 피드백("지도가 너무 복잡해 보인다") 반영, 채택한 설계:

- **기본 화면 = 깔끔한 상태**: 9개 권역 + 이름 라벨만(8도 라벨 회색, 수도권 안 서울·인천은 흰색 소라벨 상시 표시). 마커는 기본 숨김.
- **호버한 권역만 확대(1.08) + 그때 주요 지역 마커·이름 등장**: 마커를 권역 `<g>` 안에서 렌더해서 확대와 함께 움직임(어긋남 방지). 호버 권역의 큰 라벨은 잠시 숨겨 마커와 겹침 방지.
- **마커는 관광 핵심 8곳으로 정리**: 서울·인천(상시 소라벨)·수원·이천·포천·가평·파주·용인. 위성도시(안양·광명·안산 등)는 제거 — REGION_MAP_POINTS에서 좌표만 지우면 됨(데이터 기반).
- 마커 이름 위치는 좌/우/하 지정 가능(`label: "left"|"right"|"bottom"|"hidden"`)으로 겹침 수동 조정.
- 지도 힌트 문구 4개 국어 갱신("마우스를 올리면 주요 음식 동네가 나타나요").

### 지도 개선: 권역 그룹 + 관광지 마커 (2026-07-11, 세션8)

솔 요청 2건 반영:

1. **호버 확대 애니메이션** — 어느 시·도든 마우스를 올리면 1.05배 확대 + 그림자 + 이름 툴팁(콘텐츠 없으면 "Guide coming soon"). 확대된 조각이 이웃에 가려지지 않게 렌더 순서를 맨 뒤로 보내는 처리 포함.
2. **도 단위 권역 그룹 + 마커** — 광역시를 소속 도에 합쳐 **9개 권역**(수도권=서울·인천·경기 / 강원 / 충북 / 충남=+대전·세종 / 전북 / 전남=+광주 / 경북=+대구 / 경남=+부산·울산 / 제주)으로 단순화. 호버·색칠·클릭 전부 권역 단위. 그 위에 **주황 마커(점)**로 주요 관광 지역 표시 — 마커 클릭 시 지역 상세로 이동, 호버 시 지역명 툴팁.
   - **마커는 데이터 기반 자동 렌더**: 발행(published)된 지역 중 `web/lib/provinces.ts`의 `REGION_MAP_POINTS`에 좌표가 등록된 것만 그려진다. ⚠️ **새 지역 추가 시 좌표를 등록하면 지도에 자동으로 점이 생긴다** (좌표는 위경도 → viewBox 선형 변환: x=102.5·lng−12755.5, y=−105.2·lat+4067).
   - `/regions?province=`는 새 권역 키(gyeonggi 등)와 기존 시·도 키(Seoul 등) 둘 다 지원.
   - 검증: 9개 권역·마커 14개 렌더, 수도권 툴팁 "23 areas · 50 dishes", 수원 마커 클릭→/regions/suwon, 권역 클릭→수도권 23개 지역 필터, 모바일 넘침 없음, tsc·eslint·build 통과.

### 메인 개편 2주차 — SVG 지도 (2026-07-10, 세션7)

1. **지도 데이터** — `데이터수집/한국지도/korea-provinces.svg`(KOSTAT, 상업 사용 가능)에서 `web/lib/korea-map-paths.ts` 자동 생성(17개 시·도 path, 좌표 1자리 반올림으로 97KB). 자동 생성 파일이라 직접 수정 금지.

### UI 다국어 4개 국어 추가 (2026-07-09, 세션6 후반)

솔 요청: byFood처럼 우측 상단 지구본 → 언어 선택. 결정: **UI 문구만 사전 번역**(콘텐츠는 영어 유지 — 콘텐츠 번역은 스키마·운영 결정 필요라 별도 단계), **쿠키 기반**(URL 무변경 — 기존 SEO 색인 유지), 통화 선택은 가격 표시가 없어 제외.

1. **사전·헬퍼** — `web/lib/i18n/dictionaries.ts`(en/ko/ja/zh 4개 국어 UI 문구, 템플릿 문구는 함수) + `web/lib/i18n/index.ts`(`getLocale()`/`getDict()`, 쿠키 `kfood_locale`, 기본 en). 언어 타입은 기존 `SupportedLanguage`(마이페이지 선호 언어와 동일 값) 재사용. 스키마 무변경.

3. **연결 범위** — 헤더 내비·로그인 링크·푸터 8개 링크·음식 하위 탭·홈 4섹션 전체·목록 4페이지 헤더·음식 상세(섹션 제목·매운맛 라벨·메뉴 팁)·음식×지역 조합 페이지. `<html lang>`도 로케일 반영. 어드민(한국어 내부 도구)·검색·피드·마이페이지 본문은 이번 범위 제외(후속).
4. **참고** — 마이페이지 프로필의 preferred_language와 쿠키는 아직 미연동(로그인 시 동기화는 후속 과제).

검증: `npm run check` + `next build` 통과. 로컬 실확인 — 4개 언어 전부 전환 동작(내비·히어로·섹션 제목·푸터·탭·조합 페이지 문구, html lang 변경), 쿠키 저장 확인, 스위처 드롭다운 열림/닫힘 정상.

- `ADMIN_PREVIEW=true`를 `web/.env.local`에 추가하면 로그인 없이 로컬에서 `/admin`·`/mypage` 열람 가능(개발용, `NODE_ENV` 가드로 프로덕션 무효). **단, 이건 진짜 로그인이 아니라 가짜 토큰이라 실제 Supabase 쓰기(저장)는 안 됨** — 저장 기능 테스트하려면 실제 admin/editor 계정으로 로그인해야 함. 확인 끝나면 반드시 제거할 것
- `npm install`은 시스템 npm 캐시 권한 문제로 `npm install --cache <임시경로>` 필요할 수 있음
