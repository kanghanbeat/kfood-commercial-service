## 0. 먼저 알아야 할 현재 기준

이 문서는 팀원이 빠르게 같은 기준을 공유하기 위한 배포용 브리핑이다.

현재 개발 기준은 `feature/design-tokens-v2` 원격 브랜치의 최신 흐름이다. 로컬 작업트리는 문서 변경이 남아 있거나 원격보다 뒤처져 있을 수 있으므로, 새 작업 전에는 반드시 `git status`와 `git fetch`/`git pull` 상태를 확인한다.

중요한 전제:

- PR `#1`은 큰 작업 묶음이며 아직 실서비스 `main`에 머지된 것으로 보지 않는다.
- PR `#1`에는 UI/지도 작업뿐 아니라 이전 세션의 migration, auth/session, env 예시 변경도 포함된다.
- 최신 세션의 UI/지도 변경과 PR 전체의 high-risk 변경은 항상 분리해서 검토한다.

## 2. 한빛 확인 필요 항목

한빛은 모든 코드를 줄 단위로 읽는 역할이 아니다. 다만 아래 항목은 서비스 보안, 권한, production 동작에 직접 영향을 주므로 한빛 확인 또는 승인이 필요하다.

| 번호 | 확인 항목 | 한빛이 해야 할 일 | 구체적으로 볼 것 | 결정 기준 |
|---:|---|---|---|---|
| 1 | DB 스키마 변경 | migration 승인/보류 결정 | `supabase/migrations/008~011`, 새 테이블, 새 컬럼, 함수, 인덱스 | 기능에 필요하고 RLS가 안전한가 |
| 1-1 | `008_productions.sql` | 공식 제작 콘텐츠 테이블 승인 여부 확인 | `productions`, `production_tags` | 공식 콘텐츠와 UGC 분리 유지에 동의하면 승인 |
| 1-2 | `009_user_food_log.sql` | 사용자 음식 기록 유지 여부 확인 | `user_food_log` | 도감/트래커를 장기 유지할지 판단 |
| 1-3 | `010_journey_share.sql` | 여정 공유 기능 유지 여부 확인 | share token, public journey 함수 | 공유 URL 기능이 제품 방향과 맞는가 |

| 2 | RLS/권한 변경 | 정책 안전성 확인 | anon/public/authenticated/editor/admin 접근 범위 | 공개 데이터는 published만, 사용자 데이터는 본인 것만 |

## 7. 결론

현재 개발 방향은 다음 한 문장으로 정리한다.

```text
콘텐츠 SEO 사이트를 먼저 완성한다.
지도와 음식×지역 URL로 유입을 만들고,
Google Maps 저장 리스트로 실제 여행 행동에 연결한다.
커뮤니티·도감·AI·콘텐츠 번역은 유지하되,
트래픽과 운영 여력이 생긴 뒤 확장한다.
```

이 기준에서 당장의 개발 우선순위는 `P0` 정합성 정리와 PR 전략 확정, 그다음 `P1` 콘텐츠/지도/음식×지역 품질 강화다.
